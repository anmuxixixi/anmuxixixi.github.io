sashiko安装学习笔记

  • 内核补丁Sashiko检视：https://sashiko.dev/

本地 review 查找配置文件的优先顺序是：

  1. 命令行 --settings <文件>；
  2. 环境变量 $SASHIKO_CONFIG；
  3. 当前目录的 ./Settings.toml；
  4. ~/.config/sashiko.toml；如果设置了 $XDG_CONFIG_HOME，则使用$XDG_CONFIG_HOME/sashiko.toml。

因此有两种常见组织方式：

  • 用户级统一配置：~/.config/sashiko.toml；
  • 项目专用配置：仓库根目录的 Settings.toml。

项目配置更容易随仓库切换，但不要把 API key 提交到 Git。

说明：

  • provider 必须是 openai-compatible；
  • base_url 可以写 API 根地址，Sashiko 会补齐 chat completions 路径；
  • max_input_tokens 是 Sashiko 每次请求允许的输入上限，不要盲目等同于模型上下文上限；
  • max_tokens 同时影响回答和推理输出，过小可能导致 finish_reason=length；
  • concurrency 越高，速度可能越快，但 API 并发、费用和限流风险也更高；
  • effort 是否接受以及合法取值由后端模型决定；不兼容时会返回 HTTP 400；
  • 如果后端不接受 reasoning_effort，删除 [ai.openai_compat] 中的 effort。

选择推理强度

  • mid：各阶段使用中等强度，通常更快、更省；
  • high：各阶段高强度，耗时和费用显著增加；
  • dynamic：筛选、规划和报告阶段较低，关键验证阶段较高，通常是实用选择。

对 DeepSeek 等 OpenAI-compatible provider，命令行的 review effort 与模型的
reasoning_effort 支持程度并不完全等价。遇到 400 错误时，应先去掉 provider
配置里的 effort，再尝试 --effort mid 或不传该参数。

第一章：Device Mapper是什么

1.1 一句话理解Device Mapper

Device Mapper 是 Linux 内核提供的一个虚拟块设备映射框架。

它可以把一个或多个底层块设备按照指定规则，映射成一个新的虚拟块设备，供上层文件系统或应用程序使用。

例如，你有两块磁盘：

  • 磁盘 A：100 GB
  • 磁盘 B：200 GB

你希望把它们组合成一块 300 GB 的逻辑磁盘。

对上层文件系统来说，它看到的可能只是：

文件系统不需要知道底层有两块物理磁盘，更不需要自行处理磁盘 A、B 的地址分配。

DM 负责完成逻辑地址到真实块设备地址的转换。

不过，DM 能做的不仅仅是磁盘拼接。

1.2 Device Mapper可以实现哪些功能？

Device Mapper 本身是一个框架，具体功能由不同的 target（映射目标） 实现。

这些都是以 Device Mapper 为基础实现的块设备功能。

最需要理解的一点是：Device Mapper 是框架，target 才是实际处理 I/O 的功能模块。

Linux 的 LUKS 通常通过 cryptsetup 管理加密设备，而内核的 dm-crypt target 负责相应的数据路径。

cryptsetup 是用户态工具，LUKS 是磁盘加密格式和管理机制，dm-crypt 是内核中的块加密 target，三者不是同一个概念。

5.3 dm-verity：块设备完整性校验

dm-verity 是 Android 存储架构里非常重要的 target。

它的核心作用不是加密，而是：验证从块设备读取到的数据是否遭到篡改或损坏。

dm-verity 使用密码学哈希构建 Merkle Tree（哈希树），以一个可信的 Root Hash 为基础，对读取的数据进行验证。

例如读取数据块 0：

  1. DM 读取数据块。
  2. 对数据进行 Hash 计算。
  3. 根据哈希树验证对应的哈希值。
  4. 一直验证到可信根哈希。
  5. 验证通过后，数据才可以作为可信结果返回。

如果校验失败，默认的 I/O 处理会报错；不同系统还可能配置重启、panic、尝试 FEC 恢复等策略。

dm-verity 通常是只读 target，特别适合 Android 的 system、vendor 等经过校验的分区。

dm-crypt 和 dm-verity 的本质区别：

对比 dm-crypt dm-verity
主要目的 保密性 完整性
典型功能 加解密 哈希校验
是否防止数据被直接看懂 是，依赖正确的加密配置和密钥保护 否
是否检测数据修改 普通 dm-crypt 不提供认证完整性 是
通常是否可写 是 否

dm-crypt 并不自动提供 dm-verity 那样的数据完整性保证；如果需要认证或防篡改能力，还需要额外机制。

LUKS 和 dm-crypt 不是同一个东西。

  • LUKS：负责加密设备的元数据、密钥槽和密钥管理。
  • dm-crypt：负责内核中的实际数据加解密。

LUKS2 会在底层设备上保存 Header、密钥槽等元数据，真正的数据密钥通常是随机生成的 Volume Key。

用户密码主要用于解锁这个 Volume Key，而不是直接作为每个数据块的加密密钥。
